## ФАЗА 1. Корректность и честность оценки

### 1.1 Ложное отклонение формул с экспонентой — проверено
- **Файл:** `src/formula.ts`, цикл с `/\$?([A-Z]+)\$?(\d+)/gi` (~строки 76–87).
- **Проблема:** `=SUM(C2:C101)*1E5` и `+2.5e3` отклоняются: `E5`/`e3` принимаются за ссылки на ячейки.
- **Сделать:** перед проверкой ссылок удалить числовые литералы: заменить `/(?<![A-Za-z_$.\d])\d+(?:\.\d+)?(?:[eE][+-]?\d+)?/g` на пробел (уже после удаления строк в кавычках). Затем проверять ссылки. Убедиться, что `C2`, `$C$2`, `B2:B101`, `A101` по-прежнему проверяются.
- **Приёмка (тест в `tests/formula.test.ts`):** принимаются `=SUM(C2:C101)*1E5`, `=SUM(C2:C101)+2.5e3`, `=ROUND(SUM(C2:C101),2)`; отклоняются `=SUM(E5)` (при 3 колонках), `=SUM(C2:C102)`, `=SUM(AA1)`.

### 1.2 Разбор числа в ячейке: «1,000» → 1 — проверено
- **Файл:** `src/learning/Workspace.tsx`, `updateCell` (~строки 139–147).
- **Проблема:** `value.trim().replace(",", ".")` заменяет только первую запятую. `1,000` → `1`, `2,300` → `2.3`, молча. В README демо-сценарий использует «$2,300».
- **Сделать:** вынести разбор в чистую функцию `parseCellNumber(raw): { value: number } | { error: "ambiguous" | "invalid" }` в `learning/model.ts`:
  - допускает пробелы-разделители тысяч (обычный и неразрывный) и убирает их;
  - одна запятая или одна точка = десятичный разделитель, если после неё 1–2 цифры;
  - если после единственного разделителя ровно 3 цифры (`1,000`, `1.000`) → `ambiguous`; показать сообщение «Укажите число без разделителя тысяч, например 1000»;
  - несколько разных разделителей, буквы → `invalid`.
- Хранить в `draft.rows` по-прежнему либо число, либо исходную строку (чтобы `rowsError` показывал ошибку).
- **Приёмка (юнит-тест):** `"12,5"→12.5`, `"12.5"→12.5`, `"1 000"→1000`, `"1000"→1000`, `"1,000"`/`"1.000"`→ambiguous, `"1,000,000"`→invalid или 1000000 (выбери одно, зафиксируй тестом), `""`→invalid. Добавить e2e в `tests/browser/learning.spec.ts`: ввод `2,300` показывает ошибку, а не пересчитывает отчёт.

### 1.3 Подсказка выдаёт готовый ответ

- **Проблема:** `hint` содержит полную правильную формулу; копирование даёт 100 баллов.
- **Сделать (по умолчанию):** три уровня подсказки `hints: [Copy, Copy, Copy]`:
  1. идея («сначала отбери Paid, потом суммируй»);
  2. структура («используй SUMIF: диапазон условия, условие, диапазон суммы»);
  3. полный ответ — открывается отдельной кнопкой «Показать решение» с подтверждением.
  - В `LessonDraft` хранить `hintLevel: 0|1|2|3`; в `LessonResult` — `hintLevel` и `solutionRevealed: boolean`.
  - **Правило зачёта:** если решение было показано (уровень 3), урок не считается пройденным (`completed` в `LearningApp.tsx` требует `!solutionRevealed`), баллы за ремонт не более 25 из 50. Это продуктовое решение: зафиксируй в тексте разбора («Вы смотрели решение — попробуйте похожий кейс»).
  - Для уроков про решения подсказка не должна называть ответ (`email`/`hold`) прямо.
  - Старые сохранённые результаты без поля `hintLevel` читаются как 0 (обратная совместимость в `restoreLearning`).
- **Приёмка:** юнит-тесты на правило зачёта и на восстановление старых данных; e2e: открытие уровней 1→2→3, после уровня 3 урок не получает отметку «Пройдено».

### 1.4 Ответы угадываются по позиции
- **Файлы:** `src/learning/model.ts` (`diagnosis`, `transfer.options`), `Workspace.tsx` (`lesson.diagnosis.map`, `lesson.transfer.options.map`), для старого режима — `src/simulation/Simulation.tsx` (вопросы `evidence`, `limitation`).
- **Проблема:** правильный диагноз на 1-м месте в 5 из 6 уроков; правильный ответ переноса всегда на 1–2-м, ни разу на 3-м. Варианты не перемешиваются. В старом режиме два из трёх вариантов абсурдны.
- **Сделать:**
  - `shuffleOptions(options, seed)` — детерминированное перемешивание (mulberry32 или аналог). Seed = `lessonId + номер попытки по этому уроку`, чтобы порядок не прыгал при перерисовке. Применить к `diagnosis`, `transfer.options`, `decisionOptions` НЕ применять (порядок Email/Ads/Hold должен быть стабильным).

  - Старый режим: переформулировать неправильные варианты `evidence`/`limitation` так, чтобы они были реальными заблуждениями, а не очевидной глупостью («Обещанная доходность гарантирована» → «Если результат положительный, его можно масштабировать без риска»).
- **Приёмка (юнит-тест):** по 200 seed-ам правильный вариант встречается в каждой позиции (1..N) хотя бы 15% раз; порядок для одного seed повторяем; в данных каждого урока нет двух одинаковых `id`.

### 1.5 Единое правило выбора канала (дублирование логики)

## ФАЗА 2. Надёжность данных и воркеров

Уточнение владельца после ревью Фазы 1: выполнять строго в порядке **4.1 → 2.3 → 2.1 → 2.2 → 2.5 → 2.4**. Задача 4.1 перенесена в начало этой фазы.

### 2.1 Сообщения об ошибках формулы без потери причины
- **Файлы:** `src/formula.ts` (`catch {}` в `calculateGrid`, `onRange` бросает `new Error("range")`), `src/learning/Workspace.tsx` (`readableError`), `src/i18n.tsx` (`feedbackPatterns`).
- **Проблема:** причина проглатывается («Could not calculate this formula…»); в ru любое непереведённое сообщение превращается в «Не удалось проверить данные. Используйте неотрицательные числа…», что вводит в заблуждение (например, при таймауте).
- **Сделать:** ввести `type FormulaErrorCode = "syntax" | "range" | "function" | "result" | "length" | "prefix" | "timeout" | "start"` и вернуть `{ error: string; code: FormulaErrorCode; params? }`. Переводить по `code`, а не по regex. Убрать универсальную русскую «заглушку» из `readableError`: непереведённое сообщение должно показываться как есть, а не подменяться.
- **Сначала проверить (я не запускал):** как `fast-formula-parser` ведёт себя на полных колонках `=SUMIF(B:B,"Paid",C:C)` и `=SUM(C:C)`. Ожидание: понятная ошибка «Используйте диапазоны до строки 101, например C2:C101». Добавить тест, зафиксировать фактическое поведение.
- **Приёмка:** тесты на каждый `code`; в ru-режиме таймаут показывает сообщение про таймаут.

### 2.2 Один долгоживущий воркер вместо нового на каждый запрос
- **Файлы:** `src/worker-client.ts`, `src/learning/client.ts`, `src/simulation/worker.ts`.
- **Проблема:** `new Worker` + загрузка `fast-formula-parser` на каждое превью (debounce 160–200 мс) и каждую проверку; на слабых телефонах холодный старт + таймаут 4–6 с могут дать ложную ошибку. Поле `id: 1` в `worker-client.ts` не используется.
- **Сделать:** общий модуль `src/worker-pool.ts`: ленивый singleton-воркер на каждый тип воркера, запросы с монотонным `id`, ответы сопоставляются по `id`; при таймауте или `onerror` воркер `terminate()` и пересоздаётся при следующем запросе; отмена через `AbortSignal` отклоняет только свой промис. Все три клиента используют общий пул. Таймаут считать от момента фактической отправки сообщения, а не создания воркера.
- **Приёмка:** юнит-тест на пул с подменой `Worker` (fake): два параллельных запроса получают свои ответы; таймаут пересоздаёт воркер; отменённый запрос не ломает соседний. Существующие e2e проходят.

### 2.3 `formula.worker.ts` без обработки исключений

### 2.4 Хранилище: вкладки затирают друг друга, потеря всего при одной ошибке

Учебный режим: перед записью перечитывать актуальное значение и сливать: результаты объединяются по `id` (см. 2.5), черновики по `lessonId` берутся по более позднему `updatedAt` (добавить поле в `LessonDraft`, опциональное). При слиянии также сохранять максимальный `hintLevel` в пределах одной попытки, монотонный счётчик попыток и `breakdown` результатов; поздняя запись другой вкладки не должна отменять просмотр решения или терять компоненты оценки.
