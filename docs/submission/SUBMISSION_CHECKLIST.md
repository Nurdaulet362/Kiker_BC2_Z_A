## Перед разрешённой публикацией

1. Выбрать способ подготовки публичного Git-репозитория с учётом обнаруженной почты и личных путей. Не отправлять `--mirror` вместе со служебными ссылками Codex.
2. Проверить точный набор файлов и историю будущего публичного репозитория. Внутренний `CODEX_SPRINT.md` пока оставлен на месте: на него ссылаются документы. Удаление из текущего дерева само по себе не скрывает историю.
3. Сверить исходники с замороженным коммитом. README и материалы сдачи допускают отдельные документальные изменения; `src/`, тесты, зависимости, сборочные настройки и оценивание должны совпадать.
4. Если меняется состав публичного репозитория, проверить именно его чистый клон. Текущий успешный прогон относится к локальному замороженному коммиту, а не к будущей публичной ссылке.
5. После разрешения разместить выбранную статическую сборку. Для основного демо: `VITE_DEMO_ACCESS=true npm run build -- --outDir dist-demo`, каталог `dist-demo/`.
6. Проверить реальный URL в приватной вкладке: загрузку CSS/JS/worker, первый урок, тариф, Pro и плашку демо. Hash-маршруты не исправляют неверный базовый путь ассетов.
7. Проверить на физическом телефоне: ввод `2300`, формулу, 100/57/75 и следующий шаг. Не выдавать эмуляцию ширины за эту проверку.
8. Подставить только проверенные публичные ссылки в последний слайд, PDF и форму сдачи. До этого PDF остаётся материалом для просмотра, не финальным комплектом отправки.
9. Открыть резервное видео на устройстве выступающего; при необходимости озвучить по сценарию. Не выдавать подготовленный проход за результаты исследования пользователей.
