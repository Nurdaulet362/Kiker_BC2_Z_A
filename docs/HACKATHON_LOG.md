## H0b-1 — резервирование

Перед заменой исходника `.backup` сохраняется его предыдущая отличающаяся строка в `.backup.prev`, затем новая строка записывается в `.backup`, затем основной ключ. Ошибка чтения backup или записи любого резервного слота останавливает замену основного ключа. Равный текущему backup исходник не вызывает повторной ротации.

Штатное закрытие черновика подтверждается `closedAttempts` итогового состояния и не затрагивает копии. Повреждённые записи, потерянные результаты и неподтверждённое исчезновение/вытеснение черновика по-прежнему резервируются. Неизвестные события `.backup.prev` игнорируются, как и `.backup`.

Команда: `npx vitest run tests/storage-backup.test.ts tests/session-storage.test.ts && npx tsc -b`.

- Вначале была синтаксическая опечатка в новом тесте — пропущен backtick; исправлена до проверки поведения.
