# Обычная сборка и демо-доступ

Задача 4 добавляет экран тарифа без оплаты. Сайт остаётся локальным; команды ниже не публикуют его.

## Режимы

| Режим | Доступ |
| --- | --- |
| Без `VITE_DEMO_ACCESS` или любое значение, кроме точной строки `true` | Три урока `foundation` и их повтор; уроки `practice`, их сохранённые разборы и Work Trial ведут на `/#pricing` |
| `VITE_DEMO_ACCESS=true` при сборке | Все шесть уроков и Work Trial; на всех экранах постоянная плашка `Demo access — not a purchase` / «Демо-доступ — не покупка» |

Это флаг сборки. Изменение localStorage, URL или переменной окружения только при запуске preview не меняет готовый пакет. Для смены режима нужно пересобрать приложение. Новых полей доступа или оплаты в учебном состоянии нет; старые результаты не удаляются.

## Установка и обычная сборка

Один раз перед проверками:

```sh
npm ci
npx tsc -b
```

Для воспроизводимой обычной сборки явно задаём `false`, чтобы переопределить возможный локальный `.env`:

```sh
VITE_DEMO_ACCESS=false npm test
VITE_DEMO_ACCESS=false npm run build
npm run preview -- --port 4173 --strictPort
```

В другом терминале:

```sh
VITE_DEMO_ACCESS=false PLAYWRIGHT_BASE_URL=http://127.0.0.1:4173 npm run test:e2e
```

Тариф: [http://127.0.0.1:4173/#pricing](http://127.0.0.1:4173/#pricing). При отсутствии флага в окружении и `.env` обычный `npm run build` даёт такой же закрытый режим.

## Демо-сборка

Отдельный каталог позволяет держать оба варианта локально, не перезаписывая обычный `dist/`:

```sh
VITE_DEMO_ACCESS=true npm test
VITE_DEMO_ACCESS=true npm run build -- --outDir dist-demo
npm run preview -- --outDir dist-demo --port 4174 --strictPort
```

В другом терминале:

```sh
VITE_DEMO_ACCESS=true PLAYWRIGHT_BASE_URL=http://127.0.0.1:4174 npm run test:e2e
```

Демо: [http://127.0.0.1:4174/](http://127.0.0.1:4174/). `dist/` и `dist-demo/` исключены из Git. Не запускайте два e2e-прогона одновременно с одним каталогом `test-results`; используйте разные `--output`, если проверяете параллельно.

В тестах `VITE_DEMO_ACCESS` задаёт **ожидаемый** режим и должен совпадать с режимом проверяемой сборки. Тесты не определяют ожидания по наличию плашки на странице. В обычном режиме проверяется запрет доступа, в демо — прежние полные пути Pro-контента.

## Внешняя ссылка интереса

`PRO_INTEREST_URL` находится в `src/access.ts` и по умолчанию равен пустой строке. Поэтому `Get notified` / «Узнать о запуске» скрыта, а пояснение об отсутствии оплаты остаётся видимым.

Владелец может указать в этой константе адрес внешней страницы интереса и пересобрать приложение. Ссылка откроется только по нажатию пользователя в новой вкладке (`noopener noreferrer`). Приложение не содержит своей формы, не собирает e-mail и не отправляет уведомления. В тестах непустой адрес подменяется только для проверки рендера; в рабочем коде адрес остаётся пустым.

## Границы реализации

Free: три базовых занятия и повтор. Pro: гипотеза цены **$19/month**, три занятия уровня `practice` и Work Trial. Текст перед возможной ссылкой: `Payments are not connected yet. This is a product test.` / «Оплата пока не подключена. Это тест продукта».

Платежей, аккаунтов, серверной проверки подписки, подтверждения покупки и продления нет. Это ограничение интерфейса статического приложения для продуктового теста, а не защищённая сервером система платного доступа. Демо не является покупкой. Публикация требует отдельного поручения владельца.
