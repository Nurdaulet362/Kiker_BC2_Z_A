## A. Воркеры

- Очередь хранит неотвеченную работу отдельно от состояния промиса. Отмена отклоняет свой промис, но не снимает сторожевой таймер выполняемой формулы.
- Один таймер отслеживает самый старый неотвеченный запрос, включая отменённый. Следующий получает собственное время после перехода в начало очереди.
- При таймауте воркер завершается; только виновник получает `timeout`, если его промис ещё нужен. Отменённые ожидающие записи исключаются; оставшиеся активные запросы повторяются на новом воркере один раз.
- Повтор использует снимок исходного payload. Ответы старого воркера игнорируются.
- Лимит повторов конечный: если уже повторённый запрос снова оказался за другим зависшим запросом, ему возвращается существующий код `start`, а не ложный `timeout`; бесконечных повторов нет. Ошибки запуска/постинга сохраняют прежнюю обработку.
- Fake Worker покрывает все три сценария владельца, собственное время головы очереди, отменённый зависший запрос без последователей, снимок данных и предел повторов. Реальный браузерный тест блокирует первый воркер, отменяет превью и ставит за ним оценку; замена выполняет реальное вычисление, занятие завершается на 100.

## B. Сохранность

- Валидатор сообщает о потере записей. Перед заменой основного ключа сохраняются точные исходные байты в `<key>.backup`.
- Защищены повреждённые результаты, черновики, счётчики, записи подсказок, неизвестные поля и непрочитанный непустой конверт. Корректное пустое состояние не стирает полезную резервную копию.
- Проверяется также локальная сторона слияния, в том числе если её очистка не меняет основной ключ. Исходные байты не теряются при промежуточном свежем чтении до flush.
- Резервный слот один и перезаписывается; при потере данных с обеих сторон приоритет — исходная строка с диска. При ошибке резервной записи основной ключ не меняется. Состояния будущих версий обходят запись целиком.
- E2E подтверждает: невалидный результат исчез из активной истории и основного ключа, а полная исходная строка осталась в backup.

## D/E. Причины ошибок и область событий

- Типизированные статусы: `ok`, `unavailable`, `future-version`.
- Во всех трёх режимах, включая подвал Simulation, новая версия показывает: «Сохранённые данные созданы более новой версией приложения; ваши правки в этой вкладке не сохранятся». Добавлен английский перевод. Прежние сообщения для реальной недоступности хранилища сохранены.
- Неизвестные ключи, в том числе незарегистрированный backup, игнорируются до чтения. Само событие не регистрирует ключ. Clear-event обрабатывает только известные ключи.
- Проверены смена причины `unavailable → future-version → ok`, шесть способов явной регистрации ключа и отсутствие I/O/кэширования для чужих событий. E2E проверяет обе локализации предупреждения и неизменность будущих данных во всех трёх режимах.

## Неудачные промежуточные прогоны и найденные проблемы

1. B: 122 юнит-теста прошли, tsc сообщил TS2367 из-за ненужного сравнения строки с false. Исправлен тип условия выбора резервной строки; повтор прошёл.
2. F: первый запуск новых property-тестов до изменения поведения — 4 упали, 1 прошёл; воспроизведена оценка 100 вместо 75. После исправления 22 проверки прошли, 1 выявила ошибку генератора: он создал черновик hint 0 при собственной записи hint 2. Генератор исправлен по инварианту входа, без вызова проверяемого merge для подготовки данных; затем все 23 прошли.
3. C/B: первый targeted прогон — 20 прошли, 1 упал. Тест заменял данные извне и повторно ставил идентичное значение без события/свежего чтения; новая дешёвая постановка этого не перечитывает. В тест добавлено явное получение свежих данных, сохранив проверку перезаписи резервного слота. Повтор — 21/21.
4. Во время интеграции D общий прогон — 137 прошли, 1 упал: старое ожидание boolean false ещё не было заменено типизированным `ok`. После завершения обновления статусов и тестов итоговый набор прошёл.
5. Дополнительное ревью B подтвердило, что повреждённые счётчики могли возвращать пустое состояние без audit.discarded. Добавлены аудит и шесть проверок повреждённых метаданных. Это исправление вошло в итоговый прогон 147/147.
6. Один вспомогательный read-only Vite SSR probe завершил сервер во время фонового сканирования и вывел предупреждения scan-close; повтор без dependency discovery дал чистый результат. Это не был провал тестового набора.

Проверки не удалялись для получения зелёного результата; прежнее ожидание «таймаут отклоняет всю очередь» заменено тестом нового прямо запрошенного поведения. Глобальные таймауты тестов не увеличивались.
