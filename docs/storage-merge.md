# Сохранение и слияние учебного состояния

Документ создан после ревью A–F. Ранее `docs/storage-merge.md` отсутствовал; в прошлый архив он не мог попасть.

## Ключи и границы

- Учебный режим: `fix-the-report.learning.v2`, схема v2, история ограничена `MAX_RESULTS = 100`.
- Старые режимы: `fix-the-report.work-trial.v1` и `fix-the-report.cancelled-orders.v1`. Для них действуют отложенная запись, проверка версии и сообщения об ошибках; объединение истории реализовано для учебного режима.
- Язык хранится отдельным ключом. `navigator.language` не используется для этих изменений.
- Обработчик `storage` обрабатывает только ключи, которые приложение явно зарегистрировало, прочитало, записало или на которые подписалось. Неизвестный ключ и автоматически созданный `<key>.backup` не становятся известными из одного лишь события. `key === null` перечитывает только уже известные ключи.

## Путь записи

1. `setSessionItem` кладёт исходную строку в память и очередь. Нет чтения localStorage, JSON.parse и слияния на каждом нажатии. Задержка записи — 300 мс от последней правки.
2. При записи перечитывается фактическое значение на диске. Слияние также выполняется по событию `storage` и при явном запросе свежих данных перед оценкой. Последнее необходимо для учёта подсказки из другой вкладки.
3. Если схема на диске новее поддерживаемой, её ключ остаётся нетронутым. Изменения доступны в памяти; статус — `future-version`.
4. Оба доступных состояния проходят миграцию и валидацию. Сливаются результаты и метаданные; произвольные неизвестные данные не допускаются в активный интерфейс.
5. Если при восстановлении или слиянии теряются записи, перед заменой основного значения исходная строка сохраняется в `<key>.backup` **без переформатирования**. Проверяются и фактическое значение на диске, и исходные локальные данные, если они были отфильтрованы до flush. Резервирование возможно и при неизменном основном значении, когда невалидной была только локальная сторона.
6. Резервный ключ — один перезаписываемый слот, не журнал версий. Если одновременно отбрасываются разные записи с обеих сторон, приоритет имеют исходные данные с диска. При следующем удалении записей резервная копия может быть заменена; бессрочное хранение всех удалённых данных не обещается.
7. Ошибка записи резервной копии прерывает замену основного ключа. Ошибка основной записи оставляет очередь в памяти для повторной попытки. `pagehide` и `visibilitychange` при скрытии страницы вызывают синхронный flush.

Аудит восстановления отмечает отбрасывание результатов, черновиков, неизвестных или повреждённых счётчиков, записей подсказок, неизвестных полей конверта и возврат пустого состояния вместо непрочитанной непустой строки. Обычный корректный пустой конверт не заменяет полезную резервную копию. Намеренное усечение истории или удаление завершённого черновика тоже может обновить резервный слот.

## Правила слияния

| Данные | Правило |
| --- | --- |
| Результаты | Объединение по `id`, сортировка по `at`, затем `id`; последние 100. Время не служит уникальным ID. |
| Копии одного результата | Предпочтение явно сохранённому breakdown и снимку; детерминированное сравнение неизменяемых данных. Изменившиеся подсказки и ограниченные баллы не меняют приоритет исходного содержимого. |
| `breakdown` | Один согласованный набор компонентов. При раскрытии решения ремонт ограничивается 25/50, score пересчитывается как сумма. Для старой записи без breakdown поле остаётся отсутствующим: вычисленный fallback не выдаётся за явно сохранённые компоненты. |
| Черновики | Старший номер попытки; в одной попытке более поздний `updatedAt`, затем детерминированное сравнение содержимого без изменяемого уровня подсказки. |
| `attempts` | Максимум известных счётчиков и номеров попыток из сохраняемых свидетельств. |
| `closedAttempts` | Максимальный завершённый номер по уроку. Более старый черновик не может воскреснуть после удаления результата из истории. |
| `attemptHints` | Разреженная таблица `lessonId → attempt → 1\|2\|3`; объединение максимумом. Нулевые значения не сохраняются. |
| Цель обучения | Более поздний `goalUpdatedAt`, затем детерминированное разрешение равенства. |

Сведения о подсказках собираются по паре `(урок, попытка)` одним проходом до обработки результатов. Это исключает прежний вложенный поиск evidence для каждого результата. Подсказки сохраняются независимо от текущего черновика и истории: раскрытие решения в попытке 1 → начало попытки 2 → запоздавший результат попытки 1 по-прежнему означает максимум 75 баллов. Новая попытка не наследует подсказки старой.

Размер `attemptHints` растёт с количеством попыток, где использовались подсказки. Это осознанная цена сохранения сведений для произвольно запоздавшей вкладки; лимит 100 относится к результатам, а не к этим метаданным. Структуры входных состояний не изменяются. Map результатов используется для объединения по ID, а не изменяется во время обхода результатов для накопления evidence.

## Алгебраические свойства и тесты

Контракт относится к согласованным состояниям после миграции/нормализации: известные уроки, уникальные ID, сортированная история, счётчики не ниже известных попыток, согласованные баллы и подсказки. Старый или повреждённый сырой JSON сначала восстанавливается; для него буквальное `merge(a,a) === a` не обещается, поскольку сама нормализация может изменить форму данных.

`tests/learning-merge-properties.test.ts` самостоятельно строит 500 пар и троек состояний. Входы не готовятся вызовом проверяемого `mergeLearning`. Пространство — до 96 ID (6 уроков × 8 попыток × 2 результата), включая насыщенные наборы; проверяется достижение объединения ≥90 ID.

Проверяются:

- коммутативность 500 пар;
- идемпотентность 1500 состояний;
- ассоциативность 500 троек, когда **полное объединение** результатов помещается в 100;
- монотонность подсказок, завершённых попыток и счётчиков, а также отсутствие мутаций входов.

При усечении `MAX_RESULTS` ассоциативность не гарантируется: удалённое содержимое результата может понадобиться для сопоставления с более поздней копией. Это ограничение явно указано и в коде. Сведения о подсказках и завершении сохраняют монотонность независимо от усечения истории.

Сбор evidence занимает линейное время по результатам, черновикам и записям подсказок. Сортировка истории — O(R log R); сравнение содержимого конфликтующих копий также зависит от размера снимков. Непосредственный `setSessionItem` не выполняет эту работу.

## Статусы и гарантии

- `ok` — ошибки хранения сейчас нет; это не обещание, что ожидающая 300 мс правка уже попала на диск.
- `unavailable` — чтение или запись не удались; используются прежние сообщения о недоступном хранилище.
- `future-version` — «Сохранённые данные созданы более новой версией приложения; ваши правки в этой вкладке не сохранятся». Есть английский перевод.

Web Locks не добавлены (необязательный пункт G). Согласование через localStorage и storage events **не является атомарной транзакцией между вкладками**. Между чтением и записью другой процесс может изменить значение. Проверка версии перед записью, резервирование и последующее слияние уменьшают риск, но не дают гарантию сохранности при одновременном аварийном завершении всех вкладок или обходе этого протокола другим писателем.
