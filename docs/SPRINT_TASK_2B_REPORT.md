### Что именно доказывают новые e2e

### Неудачные прогоны

1. RED на прежней production-сборке задачи 3:
   `PLAYWRIGHT_BASE_URL=http://127.0.0.1:4173 npm run test:e2e -- tests/browser/review.spec.ts --grep '375px (success|failure|revealed) review'`.
   Exit 1, **3 failed**: для успеха и провала отсутствовала верхняя кнопка; для раскрытого решения отсутствовал нейтральный текст.
2. RED необязательной правки:
   `PLAYWRIGHT_BASE_URL=http://127.0.0.1:4173 npx playwright test tests/browser/navigation.spec.ts --grep 'homepage links' --workers=1 --reporter=line`.
   Exit 1, **2 failed**: старые EN/RU строки ещё говорили о пяти минутах.
3. Эти два RED-прогона были ошибочно запущены параллельно с общим каталогом `test-results`. Помимо ожидаемых падений assertions возникли ошибки `ENOENT` при сохранении trace. Это ошибка организации проверки: последующие прогоны выполнялись последовательно, а целевой прогон разбора получил отдельный `--output`. Ожидания и таймауты тестов для получения зелёного результата не ослаблялись.
4. После изменения приложения целевой прогон прошёл **9/9**, первый полный прогон новой сборки — **61/61**. Других неудачных прогонов новой сборки не было.
